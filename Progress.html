2. Blazor web app 프로젝트에서 클래스라이브러리 참조추가
3. Blazor web app 프로젝트에서 게시판 기능 구현
---------- 이 솔루션은 게시판기능을 구현할서야 . core 프로젝트에 기본이되는 클래스를 만들어줘

생성된 파일:
📁 Entities (엔티티 클래스)
• BaseEntity.cs - 모든 엔티티의 기본 클래스 (Id, CreatedAt, UpdatedAt)
• Post.cs - 게시글 엔티티 (제목, 내용, 작성자, 조회수 등)
• Comment.cs - 댓글 엔티티 (게시글 참조, 내용, 작성자)
📁 Interfaces (인터페이스)
• IRepository.cs - 기본 CRUD 작업을 위한 제네릭 인터페이스
• IPostRepository.cs - 게시글 전용 기능 (페이징, 댓글 포함 조회, 조회수 증가)
• ICommentRepository.cs - 댓글 전용 기능 (게시글별 댓글 조회)
📁 DTOs (데이터 전송 객체)
• CreatePostDto.cs - 게시글 조회용 DTO
• CreatePostDto.cs - 게시글 생성용 DTO
• UpdatePostDto.cs - 게시글 수정용 DTO
• CreateCommentDto.cs - 댓글 조회용 DTO
• CreateCommentDto.cs - 댓글 생성용 DTO

Comment.cs와 CommentDto.cs의 주요 차이점:
Comment.cs (Entity - 엔티티)
• 역할: 데이터베이스 테이블과 직접 매핑되는 도메인 모델
• 상속: BaseEntity를 상속받아 Id, CreatedAt, UpdatedAt 포함
• 관계: Post? Post - 데이터베이스 관계를 나타내는 Navigation Property
• 모든 필드 포함: IsDeleted 같은 내부 상태 관리 필드 포함
• 사용 위치: Repository, Database Context, 비즈니스 로직 내부
CommentDto.cs (Data Transfer Object - DTO)
• 역할: 클라이언트(Blazor 컴포넌트)와 서버 간 데이터 전송용
• 독립적: 다른 클래스 상속 없이 필요한 속성만 포함
• 관계 제거: Post Navigation Property 없음 (순환 참조 방지)
• 필요한 정보만: Id, CreatedAt 등 클라이언트에 필요한 데이터만
• 민감 정보 제외: IsDeleted 같은 내부 정보 숨김
• 사용 위치: API 응답, Blazor 컴포넌트, 화면 표시
왜 분리하나요?
1. 보안: 클라이언트에 불필요한 데이터 노출 방지
2. 성능: 필요한 데이터만 전송
3. 순환 참조 방지: Entity 관계로 인한 JSON 직렬화 오류 방지
4. 유연성: API 응답 구조를 Entity 구조와 독립적으로 변경 가능
